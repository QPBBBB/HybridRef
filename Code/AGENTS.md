# HybridRef

- Current scope: a minimal image-and-text reference board. Citadel is a reference, not the active application.
- Runs directly in the user's browser. React/TypeScript UI plus a Node.js service bound to 127.0.0.1; no Electron in the active application. Infinite canvas, multi-select, snapping, alignment, pan/zoom, image resize, clipboard, delete and undo/redo.
- Source: `Code/Module`; portable Windows x64 Node.js, pnpm and dependencies: `Dependencies/`; icons/images/fonts: `Code/Resource`. `Code/Module/node_modules` is a local junction to `Dependencies/Packages/node_modules`, repaired by the environment scripts after relocation. Previous Citadel implementation is archived in `Code/Module/reference/citadel` and excluded from builds/tests.
- Text items are editable resources stored beside PNGs. Do not add multiple boards, media players, recording, transcription, plugins or onboarding.
- Native document version 3 stores text layout and resource references only. Text content and styles live in separate versioned `Text_<id>_<hash>.yaml` resources. Load existing version 2 image projects; save as version 3. Preserve version 1 rejection. Write immutable text resource revisions before atomically replacing the project file; never alter resources belonging to an earlier saved revision. Text copies have independent IDs and editable content.
- Text creation, content/style editing, geometry, clipboard, selection, undo/redo and unsaved-state tracking must work with images. Preserve native text editing, multiline content and Chinese IME input; do not reuse the existing T shortcut for text creation.
- Native `.hbr` is deterministic YAML plus same-directory `<stem>Resource/` PNG files. Resource filenames must use a 13-digit Unix millisecond timestamp plus the first 8 uppercase hexadecimal characters of the image SHA256: `${UnixMilliseconds}_${HashPrefix}.png`, allocated once and stable across saves. Do not support the former full-hash filename format. All imported images normalize to compressed PNG; animated images use their first frame.
- Keep all current-project image bytes and decoded images in memory. Browser file operations use a typed HTTP client; each tab has an isolated server-side image store. Import images through Ctrl+V or drag and drop.
- Keep the repository root limited to `Code/`, `Dependencies/`, `Project/`, `.gitignore`, `README.md`, and `Start.cmd` (plus hidden `.git` metadata). The PowerShell launcher implementation lives in `Code/Module/Scripts/StartHybridRef.ps1`; generated state, logs and screenshots stay under `Code/Module/Runtime/`. Local dependency/cache files stay under `Dependencies/`. Demo: `Project/Demo/Demo.hbr` with `Project/Demo/DemoResource/`; the demo generator must refuse to overwrite an existing project.
- Windows and Edge are the assumed installed environment. Launch using bundled `Dependencies/Node/node.exe` only; do not fall back to PATH, Codex caches or npx. Keep normal launch offline. Use `Dependencies/Setup.cmd` to explicitly restore dependencies and `Dependencies/Pnpm.cmd` for development commands; preserve runtime licenses.
- Resolve the default `Project/` directory relative to the repository location. New projects request a name and immediately create `Project/<Name>/<Name>.hbr` plus `<Name>Resource/`, including the resource directory for an empty project.
- The “打开” dropdown starts with “新建项目”, followed by projects rescanned from `Project/` when opened. Creating a project requires a project-name confirmation. Project listing reads only immediate project files and does not load images, descend into resources or follow symbolic links.
- Do not show undo, redo or alignment toolbar buttons. Preserve Ctrl+Z for undo and Ctrl+Shift+Z / Ctrl+Y for redo. Ctrl+Left / Right / Up / Down Arrow push selected images in the corresponding direction. Keep plain H horizontal center, V vertical center, R push right, T push up and B push down; plain L is unbound. Require at least two selected images; do not activate while typing, menus are open, work or gestures are in progress, or Space is held. Reject modifier variants, composing input and key repeats.
- Directional push removes gaps along the requested axis, stopping edge-to-edge against another selected image with zero padding. Left/right changes only x; up/down changes only y. Preserve the other-axis positions, image sizes and stacking order. Rows or columns that do not intersect on the other axis do not block each other. Prevent selected-image overlap without flattening the selection into one row/column or forcing every image onto a shared edge. Each operation supports one-step undo/redo. Ctrl+Alt+Left / Right Arrow remain equal height / width and must not trigger directional push. The behavior follows the Push concept in the PureRef handbook; do not claim complete pixel-for-pixel PureRef compatibility.
- Equal width uses Ctrl+Alt+Right Arrow; equal height uses Ctrl+Alt+Left Arrow. Require at least two selected images, target their current mean width or height, and preserve each image's aspect ratio and center position. Both operations support undo/redo, have no toolbar buttons, and must not activate while typing or while a menu is open.
- Run `Dependencies/Pnpm.cmd typecheck`, `Dependencies/Pnpm.cmd test:run`, `Dependencies/Pnpm.cmd build`, `Dependencies/Pnpm.cmd exec playwright test` from the repository root. Validate portable environment changes with an OS-only PATH and a relocated checkout without modifying user projects.
- Preserve upstream licenses and third-party notices under `Code/Module`, and the provenance statement in `README.md`. Do not overwrite user-edited projects. Do not commit/push or publish unless requested.
- Use PascalCase for all project-owned source filenames, functions, methods, constants, variables, parameters, and local import/destructuring bindings. Active code is in `Code/Module/Source`, `Scripts`, and `E2E`; run `pnpm check:naming` (also part of `pnpm typecheck`). Preserve standard tooling filenames (`package.json`, `tsconfig.json`, `pnpm*.yaml`, `*.config.ts`), standard repository/legal filenames, external API property names, existing YAML/HTTP data keys, generated resource filenames, and archived/third-party material.
