# HybridRef

- Current scope: a minimal image-and-text reference board with editable connector arrows. Citadel is a reference, not the active application.
- The toolbar save and refresh controls use the supplied floppy-disk and circular-arrow designs converted to path-based Save.svg and Refresh.svg, with matching 34px buttons and white alpha masks. Keep accessible names, tooltips and the save dirty indicator.
- Put cleanup inside the toolbar settings dropdown as its first item. Reuse Settings.png and the existing settings-icon mask with a matching toolbar button; do not duplicate the icon asset. Keep accessible menu focus/keyboard handling, outside-click dismissal and mutual exclusion with the project menu. Canvas shortcuts must not act while the settings menu is open.
- Refresh scans Resource/ for Texture/Text/Line resource/config pairs, discovers globally unique instance IDs and reloads external edits. Agents need only write resource/config files; the app updates the v7 project index. Preserve indexed ordering and unavailable references; append new IDs deterministically. Duplicate IDs or malformed new pairs produce warnings, never arbitrary version selection. Require the current board's edits to be saved before refresh; legacy boards first save to migrate configs. Stage the load and compare the original project contents before publishing/adopting the scan. Do not rewrite resource bytes during scanning.
- Cleanup must only remove resources indexed by the destination before the current save and now unused. Preserve unindexed files, incomplete external pairs, additional config instances and externally changed/corrupt pairs. Include Markdown references from unindexed Text YAML in protection. This replaces the older broad orphan PNG/YAML cleanup rule below; never infer an unindexed resource is garbage, because agents can publish files before scanning.
- Runs directly in the user's browser. React/TypeScript UI plus a Node.js service bound to 127.0.0.1; no Electron in the active application. Infinite canvas, multi-select, snapping, alignment, pan/zoom, image resize, clipboard, delete and undo/redo.
- Source: `Code/Module`; portable Windows x64 Node.js, pnpm and dependencies: `Dependencies/`; active icons and demo inputs: `Code/Resource`. All subdirectories and filename stems under `Code/Resource` must use PascalCase; retain only assets used by the active application or its development scripts. `Code/Module/node_modules` is a local junction to `Dependencies/Packages/node_modules`, repaired by the environment scripts after relocation. Previous Citadel implementation is archived in `Code/Module/reference/citadel` and excluded from builds/tests.
- Text items are editable resources stored beside PNGs. Do not add multiple boards, media players, recording, transcription, plugins or onboarding.
- Native document version 7 is an index: retain format/version, viewport, object IDs, resource references and per-type order only. All image/text/arrow geometry lives in resource-side configs, never inline in new .hbr files. Text content and styles live in `Text_<16 uppercase timestamp hash>_<8 uppercase content hash>.yaml`; its matching .config uses hybridref-text-layout v1 with instances keyed by text ID. Read legacy inline text layouts from versions 2–6, and migrate only on explicit save, including known layouts of unavailable text. Preserve version 1 rejection. Publish resources/configs before atomically replacing the project file, then remove orphans. Text copies have independent IDs and editable content; same-directory Save As allocates independent text names. Merge independent config edits, reject conflicting edits and preserve abnormal text files, configs and references.
- Write native document version 7 for every board, so older services reject rather than discard external layouts. Keep reading versions 2/3/4/5/6. Store arrow references only in `arrows`, with content in Line YAML and geometry in its paired config; no raster asset is needed. Provide a fixed-size left-side creation icon, drag-to-draw orthogonal paths, editable endpoints/middle leg, and a fixed 24px white gear centered above the arrow's AABB opening a non-modal color/width/solid-or-dashed card. A single selected arrow has endpoint/bend handles without an AABB selection/resize box; retain group transforms for mixed selections. Use the supplied gear PNG as an alpha mask. Bound endpoints follow image/text movement and resizing; group copies remap bindings to copied IDs, standalone copies detach, and deleting targets retains the arrow with detached endpoints. Preserve mixed selection, transforms, Space fit, PNG snapshots, save/cleanup, and undo/redo. Keep arrow SVG geometry shared between canvas and snapshots: the visible shaft stops at the triangle base with a butt cap, while hit testing and endpoint handles retain the actual tip. Do not add a graphics framework.
- Selected images/text show four circular connection handles outside their edge centers. Drag directly from a handle to create a bound line without entering the toolbar tool; reveal target handles during drawing or endpoint reconnection, highlight the snapped target, and store centered bindings (offset 0.5). Keep handle hit areas, outside spacing and snap tolerance constant in screen pixels. Preserve existing saved offsets. Follow port directions in the orthogonal route and include the complete route in its frame. A click/tiny drag does not create a line; Escape/pointer cancellation restores the source selection, and Space + drag still pans. Hide connection controls during inline text editing and omit them from PNG snapshots.
- Automatic arrows with one free endpoint prefer a single L-shaped turn when the bound port direction allows it: top/bottom leave vertically, left/right leave horizontally. Toolbar drawing without bindings also starts with one turn along the dominant drag axis. Keep the route after release and save/reopen. Bound arrows with perpendicular port directions use a single L-shaped turn when the outward port rays intersect. Keep the existing detour when a direct turn would violate either port direction. Dragging a middle leg sets the optional Line YAML manualBend flag so manual routing survives save/reopen; canvas, hit paths, handles, bounds and PNG export share the same routing.
- Text creation, content/style editing, geometry, clipboard, selection, undo/redo and unsaved-state tracking must work with images. Preserve native text editing, multiline content and Chinese IME input; do not reuse the existing T shortcut for text creation.
- Tap unmodified Space to center and fit selected images/text within the canvas, preserving object geometry and selection; no selection means no viewport change. Trigger on release only when Space was not used for dragging, pointer interaction, wheel zoom, another shortcut or window blur. Keep Space + drag panning and F fitting all objects. Do not fit while editing, composing, menus/dialogs, work or a gesture are active.
- Edit text directly inside its canvas frame. The fixed-size creation icon lives at the canvas left edge; a single selected text frame shows a fixed 24px settings gear just outside its lower-right corner. Text and arrow settings share Settings.png, the same padding and fixed screen size regardless of object size or zoom. That icon opens a non-modal font/style card on the right, without a content textarea or a canvas-dimming overlay. Preserve in-progress text while switching between the frame and its style controls. Creation and settings icons have white silhouettes with transparent backgrounds and render in opaque white in normal, hover and expanded states.
- Canvas text uses fixed system SimHei (黑体), with no font picker. Use the supplied TextBold icon as an on/off bold button and three 34px square horizontal-line alignment buttons in one row with a single active option. Keep text/background color controls together, and line height/padding controls together. Font alpha is fixed at 100% without a control; the single opacity control defaults to 100% and composites the complete text surface, including Markdown and background, in both canvas and PNG snapshots. Store overall opacity in the v1 text resource's top-level opacity field, defaulting to 1 when absent. Accept legacy per-color opacity keys without using them for rendering, and write both as 1 after editing. Selection outlines and controls remain opaque.
- Text content is Markdown source in the existing text YAML `content` field. Double-click edits source in the canvas textarea; finishing renders common GFM with Marked and DOMPurify. Share sanitized HTML, styles and resolved images between canvas and PNG export. Support headings, lists, quotes, links, raster images, code, tables and tasks; math/Mermaid are outside the requested scope. Retain local images referenced only from Markdown during resource cleanup, including other projects' text resources. Keep Markdown libraries bundled for offline use; web images require a connection and must not access private network addresses.
- Native `.hbr` is deterministic YAML plus same-directory `Resource/` files. Resource filenames are `Texture_<16 uppercase timestamp hash>_<8 uppercase content hash>.png` and `Text_<16 uppercase timestamp hash>_<8 uppercase content hash>.yaml`; hash segments are SHA256 prefixes using 0-9/A-F. Allocate each timestamp hash once and retain it across saves. Do not support historical resource filename formats in the application. All imported images normalize to compressed PNG; animated images use their first frame.
- Image entries in versions 5/6/7 contain only ID and PNG reference; image order remains in `.hbr`. Store x/y/width/height in the PNG-basename `.config` as deterministic YAML (`format: hybridref-texture`, `formatVersion: 1`, `instances` keyed by image ID). Duplicate images share a PNG but retain separate instance geometry. Do not rewrite unchanged files. Merge independent instance edits and reject conflicting external edits rather than overwrite them. Missing/invalid configs or missing instance IDs must produce a per-object resource warning without inventing geometry, dropping references or blocking healthy objects. Publish configs before `.hbr`, roll back our config writes if publication fails, and protect paired configs during orphan cleanup. Same-directory Save As must allocate independent texture names to avoid shared mutable layouts. Runtime/HTTP documents retain normalized inline geometry for the renderer.
- Arrow resources use `Line_<16 uppercase timestamp hash>_<8 uppercase YAML content hash>.yaml` (`hybridref-line` v1, `arrow` field holding relative endpoints, axis/bend, styles and bindings) and the same basename `.config` (`hybridref-line-layout` v1, `instances` keyed by ID for x/y/width/height). Keep the timestamp hash stable; a changed YAML hash publishes a new pair before pruning the old one. Arrow copies and same-directory Save As allocate independent names. Preserve external changes to untouched arrows; reject conflicting edits to the same arrow. Carry current geometry into config revisions without overwriting external edits. Never rewrite unchanged pairs. Preserve bindings, selection, undo, snapshots and in-memory Save As. Config absence/corruption is a per-object resource warning; preserve its reference and raw config.
- Missing/corrupt/hash-mismatched texture, text, line and layout resources must be isolated per object, with persistent resource warnings while the rest of the board opens. Use the bundled MissingTexture icon when image geometry is valid; omit unavailable text/line objects and images without valid geometry from the editable document. Preserve their raw files, references, ordering and configs through save, cleanup and Save As, and restore them on reopen or cleanup after repair. Only manual editing removes unavailable references. Text/line YAML hashes allow proven LF/CRLF-only differences on both read and immutable-resource reuse; retain strict schema and path/symlink checks. The toolbar cleanup saves current edits and removes only orphan PNG/YAML and texture/text/line-named `.config` files. Protect Markdown-only PNGs; conservatively retain candidate PNGs when an existing unavailable text cannot be parsed. Do not recurse, follow symlinks, delete unrelated file types or other projects' references. Never prune before project publication succeeds.
- Keep all current-project image bytes and decoded images in memory. Browser file operations use a typed HTTP client; each tab has an isolated server-side image store. Import images through Ctrl+V or drag and drop.
- Ctrl+C exports selected images/text together as a losslessly encoded PNG to the browser clipboard. Crop to selection bounds at 100% board scale, independent of viewport zoom/DPI, and flatten onto the current opaque canvas background. Exclude unselected objects and editor controls; preserve text layout, clipping and missing-image aspect ratio. Write only image/png, without internal text tokens. Ctrl+V imports the snapshot as one image; Ctrl+D duplicates editable objects, and Ctrl+X retains editable cut/paste. Preserve native copying inside text inputs. Reject oversized snapshots explicitly instead of silently downsampling. Use browser-native rendering/PNG compression without an additional snapshot library.
- Keep the repository root limited to `Code/`, `Dependencies/`, `Project/`, `.gitignore`, `README.md`, and `Start.cmd` (plus hidden `.git` metadata). The PowerShell launcher implementation lives in `Code/Module/Scripts/StartHybridRef.ps1`; generated state, logs and screenshots stay under `Code/Module/Runtime/`. Local dependency/cache files stay under `Dependencies/`. Demo: `Project/Demo/Demo.hbr` with `Project/Demo/Resource/`; the demo generator must refuse to overwrite an existing project.

Use `Dependencies/Setup.cmd` to explicitly restore dependencies and `Dependencies/Pnpm.cmd` for development commands; preserve runtime licenses.

- Do not show undo, redo or alignment toolbar buttons. Preserve Ctrl+Z for undo and Ctrl+Shift+Z / Ctrl+Y for redo. Ctrl+Left / Right / Up / Down Arrow push selected images in the corresponding direction. Keep plain H horizontal center, V vertical center, R push right, T push up and B push down; plain L is unbound. Require at least two selected images; do not activate while typing, menus are open, work or gestures are in progress, or Space is held. Reject modifier variants, composing input and key repeats.
- Directional push removes gaps along the requested axis, stopping edge-to-edge against another selected image with zero padding. Left/right changes only x; up/down changes only y. Preserve the other-axis positions, image sizes and stacking order. Rows or columns that do not intersect on the other axis do not block each other. Prevent selected-image overlap without flattening the selection into one row/column or forcing every image onto a shared edge. Each operation supports one-step undo/redo. Ctrl+Alt+Left / Right Arrow remain equal height / width and must not trigger directional push. The behavior follows the Push concept in the PureRef handbook; do not claim complete pixel-for-pixel PureRef compatibility.
- Equal width uses Ctrl+Alt+Right Arrow; equal height uses Ctrl+Alt+Left Arrow. Require at least two selected images, target their current mean width or height, and preserve each image's aspect ratio and center position. Both operations support undo/redo, have no toolbar buttons, and must not activate while typing or while a menu is open.
